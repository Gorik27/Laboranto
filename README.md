# Постановка задачи для программы

## Мотивация
Наша научная группа изготавливает образцы (магнетронное напыление покрытий), делает с ними (до и после напыления) всяческие операции (химическая чистка/полировка подложек, отжиг, покрытие лаком, приделывание контактов и т.п.). Затем образцы подвергаются различным воздействиям: отжиг, коррозия и т.п.. Затем подвергаются различным исследованиям, как разрушающим (tof-sims, поляризационные электрохимические измерения), так и не разрушающим (SEM, XRD, AFM) и др. У нас каждое напыление идентифицируется уникальным номером и датой техпроцесса. В одном напылении может быть много образцов, каждый из которых тоже имеет номер (пока идет сквозная нумерация). 

При интерпретации результатов полезно иметь перед глазами полный путь каждого образца, включая комментарии исполнителей, фотографии и отчеты (например презентации ppt, или тексты doc). Также иметь возможность узнать, кто отвечал за конкретный этап, чтобы уточнить у него детали.

## Требования к программе

Для этого планируется создать базу данных (БД) и программу для работы с ней. БД не большая, образцов в каждом эксперименте обычно не больше сотни и не больше нескольких десятков операций с ними. Но БД должна поддерживать данные разных форматов: тексты, фото, сырые данные измерений (возможны специфические, бинарные форматы), презентации.
Возможно оптимальная стратегия - хранить все файлы кучей, а в БД структурировать ссылки на файлы. Для хранения данных используется линукс сервер в корпоративной сети. 

Программа для работы с БД должна позволять удобно добавлять новые образцы, файлы/данные. Искать информацию. Структурировать ход всего эксперимента. Вся информация доступна всем участникам, но есть специфичные задачи и функции в зависимости от роли:

Для руководителей: 
- Планировать эксперимент.
- Назначать ответственных исполнителей. 

Для исполнителей:
- Видеть свой план работ
- Отмечать выполнение своей работы
- Вносить данные об образцах, отчеты

Роли можно совмещать.

Такая программа должна работать на компьютере, поддерживать и виндовс, и линукс. Иметь возможность добавления андроид версии в будщем. Возможно лучший вариант - веб приложение.
Также возможна интеграция с ботами (telegram, yougile) в следующих версиях.

Для образцов нужно вести учет техпроцессов напыления. Росле окончания техпроцесса подтягивать данные с компьютера, управляющего установкой напыления, и хранить его историю по данным телеметрии и формировать отчет о нем.

Должно быть реализовано несколько способов группировки данных (по техпроцессу, по материалу подложки/слоев, по диагностикам, по воздействиям и т.д.).

4. Реализация рабочей версии.
